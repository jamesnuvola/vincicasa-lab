## Quantitative hypothesis

Tested whether a number's presence in the previous draw modifies its next-draw marginal inclusion probability.

For number n and target t:
- Global prior: q0(n,t) = prior inclusion count over outcome rows [0,t) / t.
- Lag exposure: E1(n,t) counts prior outcome rows u in [1,t) where n appeared in D(u−1).
- Lag transition count: C1(n,t) counts those rows where n also appeared in D(u).
- Shrunk conditional estimate: p1(n,t,alpha) = (C1(n,t) + alpha*q0(n,t)) / (E1(n,t) + alpha).
- Score: p1 when n is in the previous draw D(t−1), otherwise q0.
- Candidate Top-5: descending score, ties ascending number; ranking uses exact integer cross-products of rational score terms.

This is a marginal inclusion ranking, not a coherent joint probability over all 5-subsets. No fluid-dynamics mechanism is implied.

## Root-cause diagnosis

1. **Temporal instability:** discovery/validation proper scores are negative; Blind OOS point gains turn positive.
2. **Validation selection is weak:** alpha 1000 was chosen as the best among validation candidates even though every candidate's validation Brier gain was negative.
3. **No absolute Top-5 advantage over uniform:** selected-alpha blind total 485 is below the exact uniform expectation 500.625; upper-tail p=0.791490468.
4. **Multiplicity / experiment-selection risk:** none of the 28 PSR-12 tests survives Holm; the same historical tail was previously inspected by SONAR.
5. **No physical mechanism:** lag-1 inclusion is only a statistical feature hypothesis.

## Reproducibility failure and correction

The first exact-head Node 20 replay failed on the persisted JSON while the Code Mode replay matched it. The diagnosed cause was cross-runtime floating-point drift in score ranking and metric serialization. The runner now:
- ranks rational scores using exact integer cross-products (not floating comparison for Top-5 ordering);
- quantizes target Brier/log-loss differences and aggregate metrics to 9 decimals before inference/serialization;
- quantizes ledger score gains to 9 decimals;
- includes synthetic tests for exact ranking, shrinkage, strict-prefix and deterministic replay.

The correction was verified on code/results commit 17914b31c163efa910e31058a8c7c17283425958: dedicated exact-replay workflow succeeded on push run #42507461665 and PR run #42507466064; full project CI/build succeeded on push run #42507461646 and PR run #42507466083.
